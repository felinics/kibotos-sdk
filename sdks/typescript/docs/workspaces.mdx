Manage microVM workspaces through `client.workspaces` (`WorkspacesResource`). Running commands, transferring files, and opening tunnels are covered in [Exec, Files & Tunnels](./exec-files-and-tunnels).

## Create a Workspace

`client.workspaces.create(body: CreateWorkspaceRequest, opts?: RequestOptions): Promise<Workspace>`

Creates a workspace asynchronously (`POST /v1/workspaces`, HTTP `202 Accepted`). Only `template.id` is required.

```ts
import { Kibotos, type CreateWorkspaceRequest } from '@kibotos/sdk';

const client = new Kibotos();

const req: CreateWorkspaceRequest = {
  name: 'ml-sandbox',
  zone: 'global-1',
  template: { id: 'python-3.12', revision: 'rev_20260101' },
  resources: { vcpus: 4, memory_mib: 8192, disk_mib: 20480 },
  network: { mode: 'public_internet', deny: ['10.0.0.0/8'] },
  volumes: [
    { id: 'vol_data', mount_path: '/data' },
    { id: 'vol_cache', mount_path: '/cache', delete_with_workspace: true },
  ],
  packs: ['node-22'],
  timeout: { seconds: 3600, action: 'stop' },
  labels: { team: 'ml', env: 'staging' },
};

const created = await client.workspaces.create(req);
console.log(created.id, created.status); // e.g. wks_... creating
```

### `CreateWorkspaceRequest` Fields

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `template` | `WorkspaceTemplateInput` (`{ id: string; revision?: string }`) | Yes | Template ID and optional pinned revision. |
| `name` | `string` | No | Human-readable workspace name. |
| `zone` | `string` | No | Target zone ID (defaults to the organization's default zone). |
| `resources` | `WorkspaceResourcesInput` (`{ vcpus?: number; memory_mib?: number; disk_mib?: number }`) | No | Compute resource overrides. |
| `network` | `WorkspaceNetworkInput` | No | Outbound policy: `mode` plus optional `allow`, `deny`, `egresses`, and `resolvers`. See [Packs & Networking](./packs-and-networking#outbound-network-policy). |
| `volumes` | `WorkspaceVolumeAttachmentInput[]` (`{ id: string; mount_path?: string; delete_with_workspace?: boolean }`) | No | Volumes to attach at creation. Each must be in the workspace's zone. |
| `volume` | `WorkspaceVolumeAttachmentInput` | No | Legacy single-volume form of `volumes`. |
| `packs` | `string[]` | No | Up to four unique Pack IDs. |
| `timeout` | `WorkspaceTimeoutInput` (`{ seconds: number; action?: 'stop' \| 'delete' }`) | No | Auto-timeout policy. |
| `labels` | `Record<string, string>` | No | Key-value metadata labels. |

The returned `Workspace` reports attachments in `volumes` (and the legacy `volume` field), bound Packs in `packs` (`{ id, revision, provided_capabilities }`), and the active policy in `network`.

## Wait for a Target Status

`client.workspaces.wait(id: string, params: WaitWorkspaceParams, opts?: RequestOptions): Promise<Workspace>`

Long-polls `GET /v1/workspaces/{id}/wait` until the workspace reaches one of the requested statuses. When `timeoutSeconds` exceeds the server's 60-second limit, the SDK loops across `<= 60s` wait calls until the total budget elapses.

```ts
const workspace = await client.workspaces.wait(created.id, {
  status: ['available', 'failed'],
  timeoutSeconds: 180,
});

if (workspace.status === 'failed') {
  console.error('Provisioning failed:', workspace.failure?.code, workspace.failure?.message);
}
```

- `params.status`: A single `WorkspaceStatus` or an array (`'creating'`, `'available'`, `'stopping'`, `'stopped'`, `'starting'`, `'deleting'`, `'failed'`, `'unknown'`).
- `params.timeoutSeconds`: Total wait budget in seconds (defaults to `30`).
- Throws `WaitTimeoutError` (`408`) if the budget elapses, or `UnexpectedStatusError` (`409`) if the workspace reaches a terminal or unexpected status not listed in `status`.

## List and Iterate Workspaces

### Single Page (`list`)

`client.workspaces.list(params?: ListWorkspacesParams, opts?: RequestOptions): Promise<MultiZonePage<Workspace>>`

```ts
const page = await client.workspaces.list({
  status: 'available',
  zone: 'global-1',
  labels: { team: 'ml' },
  limit: 20,
});

console.log('Workspaces:', page.data.length);
console.log('Next token:', page.next_page_token);
if (page.unavailable_zones.length > 0) {
  console.warn('Unavailable zones:', page.unavailable_zones);
}
```

`ListWorkspacesParams` supports `status` (a `WorkspaceStatus` or an array), `zone`, `labels` (serialized as `label.<key>=<value>`), `limit`, and `page_token`.

### Auto-Pagination (`iterate`)

`client.workspaces.iterate(params?: ListWorkspacesParams, opts?: RequestOptions): AsyncIterable<Workspace>`

Lazily fetches pages until `next_page_token` is `null`:

```ts
for await (const ws of client.workspaces.iterate({
  status: 'available',
  labels: { env: 'prod' },
  limit: 50,
})) {
  console.log(ws.id, ws.name, ws.zone);
}
```

## Get, Update, and Delete

```ts
// Fetch a workspace by ID
const ws = await client.workspaces.get('wks_01j9...');

// Update name and/or labels (pass null to clear the name or delete a label key)
const updated = await client.workspaces.update(ws.id, {
  name: 'renamed-sandbox',
  labels: {
    owner: 'platform',
    deprecated_tag: null, // removes the label
  },
});

// Clear the workspace name
await client.workspaces.update(ws.id, { name: null });

// Delete asynchronously (202 Accepted)
const deleting = await client.workspaces.delete(ws.id);
console.log(deleting.status); // 'deleting'
```

## Resize a Workspace

`update` also accepts `resources`. A workspace must be `'stopped'` or `'failed'` to change vCPUs or memory or to grow the root disk. The root disk cannot shrink.

```ts
await client.workspaces.stop(ws.id);
await client.workspaces.wait(ws.id, { status: 'stopped', timeoutSeconds: 120 });

const resized = await client.workspaces.update(ws.id, {
  resources: { vcpus: 4, memory_mib: 8192, disk_mib: 40960 },
});
console.log(resized.resources);

await client.workspaces.start(ws.id);
```

## Start and Stop

```ts
// Gracefully stop an available workspace
await client.workspaces.stop(ws.id);
await client.workspaces.wait(ws.id, { status: 'stopped', timeoutSeconds: 60 });

// Force an immediate power-off
await client.workspaces.stop(ws.id, { force: true });

// Start a stopped or failed workspace, optionally with a fresh timeout
await client.workspaces.start(ws.id, {
  timeout: { seconds: 7200, action: 'stop' },
});
await client.workspaces.wait(ws.id, { status: 'available', timeoutSeconds: 120 });
```

## Update Timeout Policy

`client.workspaces.setTimeout(id: string, body: SetWorkspaceTimeoutRequest, opts?: RequestOptions): Promise<Workspace>`

Resets the expiration policy on an available workspace:

```ts
const extended = await client.workspaces.setTimeout(ws.id, {
  seconds: 7200,
  action: 'stop', // 'stop' | 'delete'
});
console.log('New expiry:', extended.timeout?.expires_at);
```

## Configure Outbound Network

`client.workspaces.setNetwork(id: string, body: SetWorkspaceNetworkRequest, opts?: RequestOptions): Promise<Workspace>`

Replaces the whole outbound policy (`PUT /v1/workspaces/{id}/network`). `network.applied` is `null` while the workspace is not running and becomes `true` once a running workspace has confirmed the policy.

```ts
const isolated = await client.workspaces.setNetwork(ws.id, { mode: 'deny_all' });
console.log(isolated.network.mode, isolated.network.applied);
```

Allow and deny lists, egresses, resolvers, and `drain_seconds` are covered in [Packs & Networking](./packs-and-networking#outbound-network-policy).

## Attach and Detach Volumes

`client.workspaces.setVolumes(id: string, body: SetWorkspaceVolumesRequest, opts?: RequestOptions): Promise<Workspace>`

Replaces all volume bindings on a `'stopped'` or `'failed'` workspace (`PUT /v1/workspaces/{id}/volumes`). Send every binding you want to keep. An empty array detaches all volumes.

```ts
const withVolumes = await client.workspaces.setVolumes(ws.id, {
  volumes: [
    { id: 'vol_data', mount_path: '/data' },
    { id: 'vol_cache', mount_path: '/cache', delete_with_workspace: true },
  ],
});
console.log(withVolumes.volumes?.map((v) => `${v.id} at ${v.mount_path}`));

// Detach everything
await client.workspaces.setVolumes(ws.id, { volumes: [] });
```

The single-volume methods remain available. `attachVolume` leaves the workspace with only the given volume and `detachVolume` removes every attachment, so use `setVolumes` when a workspace has more than one volume.

```ts
await client.workspaces.attachVolume(ws.id, {
  id: 'vol_01j9...',
  mount_path: '/data',
  delete_with_workspace: false,
});
await client.workspaces.detachVolume(ws.id);
```

## Set Packs

`client.workspaces.setPacks(id: string, body: SetWorkspacePacksRequest, opts?: RequestOptions): Promise<Workspace>`

Replaces the Pack list with up to four unique Pack IDs (`PUT /v1/workspaces/{id}/packs`). The change takes effect on the next start. An empty array clears the list.

```ts
const withPacks = await client.workspaces.setPacks(ws.id, { packs: ['node-22'] });
console.log(withPacks.packs);
```

Browse available Packs with `client.packs`. See [Packs & Networking](./packs-and-networking#packs).
