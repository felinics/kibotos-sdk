`@kibotos/sdk` throws typed errors, retries transient failures, generates `Idempotency-Key` headers for `POST` mutations, and supports cancellation with `AbortSignal`.

## Error Hierarchy

Every error thrown by `@kibotos/sdk` extends `KibotosError`:

```text
KibotosError
├── APIConnectionError          (network failure or client-side request timeout)
└── KibotosAPIError             (non-2xx HTTP response)
    ├── AuthenticationError     (HTTP 401)
    ├── PermissionDeniedError   (HTTP 403)
    ├── NotFoundError           (HTTP 404)
    ├── WaitTimeoutError        (HTTP 408 wait_timeout)
    ├── ConflictError           (HTTP 409)
    │   └── UnexpectedStatusError (HTTP 409 with code 'unexpected_status')
    └── RateLimitError          (HTTP 429, exposes retryAfterMs)
```

### `KibotosAPIError` Properties

| Property | Type | Description |
| --- | --- | --- |
| `status` | `number` | HTTP status code returned by the API. |
| `code` | `string` | Machine-readable error code (e.g. `'workspace_not_found'`, `'invalid_state'`). |
| `message` | `string` | Human-readable error message. |
| `requestId` | `string \| undefined` | Server `request_id` (or `Request-Id` response header) for support and tracing. |
| `retryable` | `boolean` | Whether the API marked this error as safe to retry. |
| `details` | `Record<string, unknown> \| undefined` | Optional structured metadata from the API error envelope. |
| `headers` | `Headers \| undefined` | Raw HTTP response headers. |

`RateLimitError` additionally exposes `retryAfterMs: number | undefined`, parsed from the response's `Retry-After` header (supporting both delta-seconds and HTTP-date formats).

### Common Error Codes

| Code | Class | When |
| --- | --- | --- |
| `invalid_state` | `ConflictError` | The workspace is in the wrong status, such as `setVolumes` or a resize on a running workspace. |
| `volume_attached` | `ConflictError` | Deleting a volume that is bound to a workspace. |
| `resource_in_use` | `ConflictError` | Deleting an egress or resolver that a workspace policy still references. |
| `file_exists` | `ConflictError` | `makeDir` on an existing path, or `writeFile` with `createOnly` on an existing file. |
| `desktop_not_enabled` | `ConflictError` | Opening the desktop stream on a workspace without a `desktop.v1` Pack. |
| `unexpected_status` | `UnexpectedStatusError` | `wait()` observed a status outside the requested targets. |
| `wait_timeout` | `WaitTimeoutError` | `wait()` ran out of time. |

### Catching Specific Errors

```ts
import {
  APIConnectionError,
  AuthenticationError,
  ConflictError,
  Kibotos,
  KibotosAPIError,
  NotFoundError,
  PermissionDeniedError,
  RateLimitError,
  UnexpectedStatusError,
  WaitTimeoutError,
} from '@kibotos/sdk';

const client = new Kibotos();

try {
  await client.workspaces.wait('wks_01j9...', {
    status: 'available',
    timeoutSeconds: 60,
  });
} catch (err) {
  if (err instanceof AuthenticationError) {
    console.error('Check KIBOTOS_API_KEY:', err.requestId);
  } else if (err instanceof PermissionDeniedError) {
    console.error('Quota or permission error:', err.code, err.details);
  } else if (err instanceof NotFoundError) {
    console.error('Workspace does not exist:', err.code);
  } else if (err instanceof UnexpectedStatusError) {
    console.error('Workspace reached unexpected state:', err.details);
  } else if (err instanceof WaitTimeoutError) {
    console.error('Timed out waiting:', err.details);
  } else if (err instanceof ConflictError) {
    console.error('State conflict:', err.code, err.message);
  } else if (err instanceof RateLimitError) {
    console.error('Rate limited; retry after ms:', err.retryAfterMs);
  } else if (err instanceof KibotosAPIError) {
    console.error('API error:', err.status, err.code, err.requestId);
  } else if (err instanceof APIConnectionError) {
    console.error('Network or timeout failure:', err.message);
  } else {
    throw err;
  }
}
```

## Automatic Retries & `Retry-After`

By default, `new Kibotos()` retries up to `maxRetries: 3` times with exponential backoff and jitter (`500ms` initial delay, capped at `8000ms`, jitter factor `[0.5, 1.0)`).

Requests are automatically retried when:

- A transient network or timeout error occurs (`APIConnectionError`)
- The API returns HTTP `429`, `500`, `502`, `503`, or `504`
- The API returns `error.retryable === true` (except `408 wait_timeout` inside `wait()`, which is handled directly by the chunked wait loop)

When the server includes a `Retry-After` header (delta-seconds or HTTP-date), the SDK honors that exact delay instead of exponential backoff.

To disable retries globally:

```ts
const client = new Kibotos({ maxRetries: 0 });
```

### Requests That Are Never Retried

`exec`, `execStream`, `writeFile`, `makeDir`, `moveFile`, and `deleteFile` are sent exactly once, regardless of `maxRetries`. They can have side effects or carry a body that cannot be replayed, so decide in your own code whether a failed call is safe to repeat.

## Idempotency (`Idempotency-Key`)

For every control-plane `POST` request (`workspaces.create`, `workspaces.start`, `workspaces.stop`, `workspaces.setTimeout`, `volumes.create`, `volumes.resize`, `exposures.create`, `egresses.create`, `resolvers.create`), the SDK generates a UUID v4 `Idempotency-Key` header if one is not provided, and **reuses the exact same key across all retry attempts**.

`exec`, `makeDir`, and `moveFile` are not idempotent and never send an `Idempotency-Key`.

To supply your own deterministic key across process restarts or job retries:

```ts
const workspace = await client.workspaces.create(
  {
    name: 'job-42',
    template: { id: 'python-3.12' },
  },
  {
    idempotencyKey: 'job-42-workspace-create-v1',
  },
);
```

## Request Timeouts & `AbortSignal` Cancellation

Pass `signal` or `timeoutMs` in `RequestOptions` on any method to cancel in-flight requests, pending retry backoff sleeps, or chunked `wait()` loops:

```ts
const controller = new AbortController();
setTimeout(() => controller.abort(new Error('User cancelled')), 10_000);

const workspace = await client.workspaces.wait(
  'wks_01j9...',
  { status: 'available', timeoutSeconds: 180 },
  { signal: controller.signal },
);
```

Caller-initiated aborts propagate immediately without triggering retries.

### Default Timeouts

| Method | Default client timeout |
| --- | --- |
| Most methods | `timeoutMs` from the client options (`30000`). |
| `wait` | Each long-poll chunk gets at least its window plus 15 seconds. |
| `exec` | `timeout_seconds` (or `30`) plus 15 seconds. |
| `execStream`, `readFile`, `writeFile` | No deadline. Pass `timeoutMs` or `signal`. |

A per-request `timeoutMs` overrides the default in every case.

## Streaming and WebSocket Errors

- `execStream` throws a `KibotosAPIError` when the request itself is rejected. A failure after the stream opens is delivered as an `error` event instead.
- `connectWS`, `connectTunnel`, `connectDesktop`, and `connectProxy` return a `WebSocket` immediately. Handshake and connection failures surface through its `error` and `close` events. Stream-level failures on the multiplexed channel arrive as `error` control frames.
- `APIConnectionError` is thrown synchronously when no usable `WebSocket` implementation is available. See [WebSocket runtime support](./exec-files-and-tunnels#websocket-runtime-support).
