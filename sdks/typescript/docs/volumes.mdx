---
title: Volumes
description: Create, list, update, resize, delete, and wait for persistent Kibotos volumes, and attach them to workspaces, with @kibotos/sdk.
---

Manage persistent storage volumes through `client.volumes` (`VolumesResource`). A workspace can mount one or more volumes from its own zone. Bind them at creation, or while the workspace is stopped or failed.

## Create a Volume

`client.volumes.create(body: CreateVolumeRequest, opts?: RequestOptions): Promise<Volume>`

Creates a persistent volume asynchronously (`POST /v1/volumes`, HTTP `202 Accepted`). `size_gib` is required.

```ts
import { Kibotos } from '@kibotos/sdk';

const client = new Kibotos();

const created = await client.volumes.create({
  name: 'datasets-cache',
  zone: 'global-1',
  size_gib: 50,
  labels: { team: 'ml' },
});

const volume = await client.volumes.wait(created.id, {
  status: ['available', 'failed'],
  timeoutSeconds: 120,
});
console.log(volume.id, volume.status, `${volume.size_gib} GiB`);
```

### `CreateVolumeRequest` Fields

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `size_gib` | `number` | Yes | Volume capacity in GiB. |
| `name` | `string` | No | Human-readable volume name. |
| `zone` | `string` | No | Target compute zone ID (defaults to organization default zone). |
| `labels` | `Record<string, string>` | No | Key-value metadata labels. |

## List and Iterate Volumes

### Single Page (`list`)

`client.volumes.list(params?: ListVolumesParams, opts?: RequestOptions): Promise<MultiZonePage<Volume>>`

```ts
const page = await client.volumes.list({
  zone: 'global-1',
  attached: false,
  labels: { team: 'ml' },
  limit: 25,
});

for (const vol of page.data) {
  console.log(vol.id, vol.size_gib, vol.status, vol.workspace_id);
}
```

### Auto-Pagination (`iterate`)

`client.volumes.iterate(params?: ListVolumesParams, opts?: RequestOptions): AsyncIterable<Volume>`

```ts
for await (const vol of client.volumes.iterate({ attached: true })) {
  console.log(`${vol.id} attached to ${vol.workspace_id}`);
}
```

## Get and Update a Volume

```ts
// Fetch by ID
const vol = await client.volumes.get('vol_01j9...');

// Update name and labels (pass null to clear name or delete a label key)
const updated = await client.volumes.update(vol.id, {
  name: 'datasets-v2',
  labels: {
    tier: 'hot',
    old_label: null,
  },
});
```

## Resize a Volume

`client.volumes.resize(id: string, body: ResizeVolumeRequest, opts?: RequestOptions): Promise<Volume>`

Grows an existing `'available'` volume asynchronously (`POST /v1/volumes/{id}/resize`, HTTP `202 Accepted`). Wait for `'available'` to confirm completion (volumes bound to a stopped or failed workspace remain `'available'` and can be resized):

```ts
await client.volumes.resize(vol.id, { size_gib: 100 });

const resized = await client.volumes.wait(vol.id, {
  status: ['available', 'failed'],
  timeoutSeconds: 180,
});
console.log('New size:', resized.size_gib, 'GiB');
```

## Delete a Volume

`client.volumes.delete(id: string, opts?: RequestOptions): Promise<Volume>`

Deletes an unbound volume (`workspace_id === null`) asynchronously (`DELETE /v1/volumes/{id}`, HTTP `202 Accepted`). Attempting to delete a bound volume throws `ConflictError` (`volume_attached`).

```ts
const deleting = await client.volumes.delete(vol.id);
console.log(deleting.status); // 'deleting'
```

## Wait for Volume Status

`client.volumes.wait(id: string, params: WaitVolumeParams, opts?: RequestOptions): Promise<Volume>`

Supported `VolumeStatus` values: `'creating'`, `'available'`, `'attached'`, `'resizing'`, `'deleting'`, `'failed'`, `'lost'`, `'unknown'`.

Volume statuses follow native Kibotos 1:1 semantics: `workspace_id` expresses whether a volume is bound to a workspace; `'available'` means ready and not currently mounted to a running workspace (including volumes bound to a stopped/failed workspace); `'attached'` means mounted to a running workspace; `'lost'` means the underlying storage pool was lost and data is unrecoverable.

```ts
const ready = await client.volumes.wait('vol_01j9...', {
  status: ['available', 'failed'],
  timeoutSeconds: 90,
});
```

As with workspaces, `timeoutSeconds` defaults to `30` and automatically loops across `<= 60s` server long-poll windows when larger than `60`.

## Attach Volumes to a Workspace

Volume bindings are managed on the workspace. Pass `volumes` to `workspaces.create`, or replace the full list on a `'stopped'` or `'failed'` workspace with `workspaces.setVolumes`:

```ts
const ws = await client.workspaces.create({
  template: { id: 'python-3.12' },
  zone: volume.zone,
  volumes: [{ id: volume.id, mount_path: '/data', delete_with_workspace: false }],
});

// Replace the bindings later (the workspace must be stopped or failed)
await client.workspaces.setVolumes(ws.id, {
  volumes: [
    { id: volume.id, mount_path: '/data' },
    { id: 'vol_cache', mount_path: '/cache' },
  ],
});
```

| Binding field | Type | Description |
| --- | --- | --- |
| `id` | `string` | Volume ID. The volume must be unbound and in the workspace's zone. |
| `mount_path` | `string` | Absolute mount path inside the workspace. |
| `delete_with_workspace` | `boolean` | Delete the volume when the workspace is deleted. |

A bound volume reports the workspace in `workspace_id`. See [Workspaces](./workspaces#attach-and-detach-volumes) for `setVolumes` and the single-volume `attachVolume` / `detachVolume` methods.
