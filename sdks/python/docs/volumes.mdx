---
title: Volumes
description: Create, list, update, resize, delete, and wait for persistent Kibotos volumes, and attach them to workspaces, in Python.
---

Manage persistent storage volumes via `client.volumes` (`VolumesResource` on `Kibotos`, `AsyncVolumesResource` on `AsyncKibotos`). A workspace can mount one or more volumes from its own zone. Bind them at creation, or while the workspace is stopped or failed.

## Create a Volume

`client.volumes.create(*, size_gib, name=None, zone=None, labels=None, idempotency_key=None) -> Volume`

Creates a persistent volume asynchronously (`POST /v1/volumes`, HTTP `202 Accepted`). `size_gib` is required.

```python
from kibotos import Kibotos

with Kibotos() as client:
    created = client.volumes.create(
        size_gib=50,
        name="datasets-cache",
        zone="global-1",
        labels={"team": "ml"},
    )
    vol = client.volumes.wait(created.id, status=["available", "failed"], timeout=120)
    print(f"{vol.id}: {vol.size_gib} GiB ({vol.status})")
```

## List and Iterate Volumes

### Single Page (`list`)

Returns a `VolumePage` (`data: list[Volume]`, `unavailable_zones: list[str]`, `next_page_token: str | None`):

```python
page = client.volumes.list(
    zone="global-1",
    attached=False,
    labels={"team": "ml"},
    limit=25,
)
for vol in page.data:
    print(vol.id, vol.name, vol.size_gib, vol.status, vol.workspace_id)
```

### Auto-Pagination (`iterate`)

```python
# Sync
for vol in client.volumes.iterate(attached=True):
    print(f"{vol.id} -> {vol.workspace_id}")

# Async
async for vol in async_client.volumes.iterate(zone="global-1"):
    print(vol.id, vol.size_gib)
```

## Get and Update (`UNSET` PATCH Semantics)

Just like `workspaces.update()`, `volumes.update()` omits `name` when left at its default `UNSET` sentinel, and sends `{"name": null}` when you explicitly pass `name=None`:

```python
vol = client.volumes.get("vol_01j9...")

# Update name and labels (None label value deletes the key)
vol = client.volumes.update(
    vol.id,
    name="datasets-v2",
    labels={"tier": "hot", "old_label": None},
)

# Clear name only
vol = client.volumes.update(vol.id, name=None)
```

## Resize a Volume

`client.volumes.resize(volume_id, *, size_gib, idempotency_key=None) -> Volume`

Grows an existing `"available"` volume asynchronously (`POST /v1/volumes/{id}/resize`, HTTP `202 Accepted`; volumes bound to a stopped/failed workspace remain `"available"` and can be resized):

```python
client.volumes.resize(vol.id, size_gib=100)
vol = client.volumes.wait(
    vol.id,
    status=["available", "failed"],
    timeout=180,
)
print("New size:", vol.size_gib, "GiB")
```

## Delete a Volume

`client.volumes.delete(volume_id) -> Volume`

Deletes an unbound volume (`workspace_id is None`) asynchronously (`DELETE /v1/volumes/{id}`, HTTP `202 Accepted`). Attempting to delete a bound volume raises `ConflictError` (`volume_attached`).

```python
deleting = client.volumes.delete(vol.id)
print(deleting.status)  # "deleting"
```

## Wait for Volume Status

`client.volumes.wait(volume_id, *, status, timeout=30.0) -> Volume`

Valid `VolumeStatus` values: `"creating"`, `"available"`, `"attached"`, `"resizing"`, `"deleting"`, `"failed"`, `"lost"`, `"unknown"`. Volume statuses follow native Kibotos 1:1 semantics: `workspace_id` expresses workspace binding; `"available"` means ready and not currently mounted to a running workspace (including volumes bound to a stopped/failed workspace); `"attached"` means mounted to a running workspace; `"lost"` means the underlying storage pool was lost and data is unrecoverable. Timeouts exceeding `60` seconds automatically loop across `<= 60s` server wait windows.

```python
ready = client.volumes.wait("vol_01j9...", status=["available", "failed"], timeout=90.0)
```

## Attach Volumes to a Workspace

Volume bindings are managed on the workspace. Pass `volumes` to `workspaces.create`, or replace the full list on a `"stopped"` or `"failed"` workspace with `workspaces.set_volumes`:

```python
ws = client.workspaces.create(
    template="python-3.12",
    zone=vol.zone,
    volumes=[{"id": vol.id, "mount_path": "/data", "delete_with_workspace": False}],
)

# Replace the bindings later (the workspace must be stopped or failed)
client.workspaces.set_volumes(
    ws.id,
    volumes=[
        {"id": vol.id, "mount_path": "/data"},
        {"id": "vol_cache", "mount_path": "/cache"},
    ],
)
```

| Binding field | Type | Description |
| --- | --- | --- |
| `id` | `str` | Volume ID. The volume must be unbound and in the workspace's zone. |
| `mount_path` | `str` | Absolute mount path inside the workspace. |
| `delete_with_workspace` | `bool` | Delete the volume when the workspace is deleted. |

Bindings are `WorkspaceVolumeInput` models or plain dicts. A bound volume reports the workspace in `workspace_id`. See [Workspaces](./workspaces#attach-and-detach-volumes) for `set_volumes` and the single-volume `attach_volume` / `detach_volume` methods.
