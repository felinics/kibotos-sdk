Manage microVM workspaces using `kibo workspace` (aliases: `ws`, `workspaces`).

## Create a Workspace

Run `kibo ws create` with no flags in an interactive terminal to choose a template and optionally name the workspace. Supply flags for resource overrides and other settings. Async lifecycle commands (`create`, `start`, `stop`, `restart`, `delete`, `network`) **wait until completion by default** (pass `--no-wait` to return immediately):

```bash
kibo workspace create \
  -t python-3.12 \
  -n agent-sandbox \
  -z global-1 \
  --vcpus 2 --memory 4Gi --disk 20Gi \
  --network public_internet \
  --timeout 1h --timeout-action stop \
  -l team=ml -l env=dev \
  --json
```

### `kibo workspace create` Flags

| Flag | Required | Default | Description |
| --- | --- | --- | --- |
| `-t`, `--template <id>` | Yes (prompted in TTY) | — | Template ID (also accepts `template@revision`). |
| `--revision <rev>` | No | template default | Specific template revision ID. |
| `-n`, `--name <name>` | No | — | Human-readable workspace name. |
| `-z`, `--zone <zone>` | No | org default zone | Target zone ID. |
| `--vcpus <n>` | No | template default | vCPU count override. |
| `--memory <size>` | No | template default | Memory allocation (`4Gi`, `4096`; bare integer is MiB). |
| `--disk <size>` | No | template default | Root disk size (`20Gi`, `20480`; bare integer is MiB). |
| `--network <mode>` | No | API default | Outbound network mode: `public_internet` or `deny_all`. Add allow, deny, egress, and resolver rules after creation with [`kibo ws network`](packs-and-networking#referencing-networking-resources). |
| `--volume <vol_id:/path>` | No | — | Repeat for multiple bindings. A single legacy volume ID or name can be paired with `--mount-path`. |
| `--pack <pack_id>` | No | — | Bind a Pack. Repeat for up to four unique IDs. |
| `--desktop` | No | `false` | Attach a Pack that provides `desktop.v1` and show the Desktop URL in human output. The Pack counts toward the four-Pack limit. |
| `--open` | No | `false` | Open the Desktop URL when the new workspace is available. Requires `--desktop`. |
| `--console-url <url>` | No | resolved console URL | Override the HTTP or HTTPS base URL for the Desktop link. |
| `--mount-path <path>` | No | — | Mount path inside the workspace (e.g. `/data`; requires `--volume`). |
| `--delete-volume` | No | `false` | Delete the attached volume when this workspace is deleted (requires `--volume`). |
| `--timeout <dur>` | No | — | Auto-timeout duration (`1h`, `30m`, `3600`; bare integer is seconds). |
| `--timeout-action <action>` | No | — | Action on timeout expiration: `stop` or `delete` (requires `--timeout`). |
| `-l`, `--label <key=value>` | No | — | Workspace label (repeatable). |
| `--wait` | No | `true` | Block until workspace status reaches `available` (default `true`). |
| `--no-wait` | No | `false` | Return immediately without waiting for completion. |
| `--wait-timeout <dur>` | No | `5m` (`300s`) | Maximum duration to wait. |

## Remote desktop

```bash
kibo ws create -t debian -n desktop-dev --desktop --open
kibo desktop                        # Pick a workspace
kibo desktop desktop-dev --open     # Use a workspace name or ID
kibo ws desktop wks_123 --start --restart --no-input --json
kibo desktop wks_123 --no-input -q
```

`kibo desktop` and `kibo ws desktop` attach a Pack that provides `desktop.v1` when the workspace needs one. The Pack takes effect on the next start. In a terminal, the command offers to start a stopped workspace or restart an available workspace that needs the Pack. In automation, use `--start` for a stopped workspace and `--restart` to activate a newly attached Pack on a running workspace. In a terminal, `-y` accepts either prompt. If you defer a restart, stop and start the workspace when ready.

Desktop waits for a requested start or restart to reach `available` by default. Use `--wait-timeout` to set the wait limit. With `--no-wait`, a restart still waits for the stop before sending the start request. `--open` launches the browser once the command has an available workspace and any required restart has been performed.

The browser URL uses `<console-url>/desktop/<workspace-id>` and includes `?org=<organization-id>` when the organization is known from the active profile or an override. The console base resolves from `--console-url`, `KIBOTOS_CONSOLE_URL`, `KIBO_CONSOLE_URL`, the profile's `console_url`, or the default `https://dash.kibo.to`, in that order.

`kibo desktop --json` returns `workspace_id`, `status`, `desktop_enabled`, `pack_id`, `restart_required`, and `url`. When it attaches the Pack to an available workspace and leaves it running, `restart_required` is `true`. Quiet mode prints just the URL. For `ws create --desktop`, JSON returns the workspace object and quiet mode prints the workspace ID.

## List and Inspect Workspaces

When neither `--limit` nor `--page-token` is provided, `kibo workspace list` automatically collects all pages across zones:

```bash
# List all available workspaces matching labels
kibo ws list --status available --zone global-1 --label team=ml

# Fetch a single page in JSON
kibo ws list --limit 20 --page-token <token> --json

# Inspect a specific workspace
kibo ws get wks_01j9...
```

Valid `--status` values: `creating`, `available`, `stopping`, `stopped`, `starting`, `deleting`, `failed`, `unknown`.

## Update Name and Labels

Specify at least one of `--name`, `--clear-name`, `--label`, or `--unset-label`. `--name` and `--clear-name` are mutually exclusive; `--label` and `--unset-label` are repeatable:

```bash
# Rename and update/remove labels
kibo ws update wks_01j9... \
  --name production-worker \
  --label env=prod \
  --unset-label temp

# Clear the workspace name (sets name to null)
kibo ws update wks_01j9... --clear-name
```

## Start, stop, restart, and delete

All lifecycle commands accept a workspace ID or unique name (or prompt interactively in a TTY if omitted) and **wait by default** (pass `--no-wait` to return immediately, or `--wait-timeout <dur>` to override the `5m` wait window):

```bash
# Gracefully stop (waits until stopped by default)
kibo ws stop agent-sandbox

# Force immediate power-off (asks confirmation in TTY unless -y is passed)
kibo ws stop agent-sandbox --force -y

# Start a stopped workspace with a fresh 2-hour auto-stop timeout
kibo ws start agent-sandbox --timeout 2h --timeout-action stop

# Restart with a new timeout for the start
kibo ws restart agent-sandbox --timeout 2h --timeout-action stop --no-input --json

# Delete and wait until removed (returns status "deleted" when complete)
kibo ws delete agent-sandbox -y
```

A restart always waits until the workspace is stopped. Use `--no-wait` to skip the final wait for `available`. `--force` powers off immediately and asks for confirmation in a terminal unless you pass `-y`.

## Apply configuration changes on a running workspace

Resize and volume changes require an offline workspace. On a running workspace, the terminal asks once before stopping, applying the change, starting again, and waiting for availability. Pack changes can be saved while running and take effect on the next start. The terminal asks once before saving and restarting. The default answer is yes, and declining cancels before any change.

For scripts, pass `--restart` to opt in explicitly. Without it, these commands leave the power state alone. The API rejects running resize and volume changes with `invalid_state`, and the next start activates saved Pack changes. `--wait-timeout` sets the limit for each transition and defaults to five minutes. If an offline mutation fails after stopping the workspace, the command returns the API error and leaves the workspace stopped.

## Update Timeout Policy

Extend or change the auto-timeout on a workspace (`--seconds` accepts durations like `2h` or bare seconds like `7200`; prompted in TTY if omitted):

```bash
kibo ws timeout agent-sandbox --seconds 2h --action stop
```

## Configure Outbound Network

Switch between `public_internet` and `deny_all` (waits until `network.applied` becomes `true` by default; pass `--no-wait` for immediate return):

```bash
kibo ws network agent-sandbox --mode deny_all
kibo ws network agent-sandbox --mode public_internet
```

The `--mode` form replaces the whole policy. Combine it with repeatable `--allow` and `--deny` (an IP address or CIDR each), one `--egress egress_id=IP_OR_CIDR[,IP_OR_CIDR...]`, one `--resolver resolver_id[=egress_id]`, and `--drain-seconds` (`0`–`3600`). `deny_all` requires all four rule lists to be empty.

```bash
kibo ws network agent-sandbox --mode public_internet \
  --deny 10.0.0.0/8 --allow 10.1.2.3 --drain-seconds 60 --no-input --json
```

To edit one rule and keep the rest, use `kibo ws network allow`, `deny`, `use-egress`, and `use-resolver`. [Packs and networking](packs-and-networking#edit-one-workspace-network-rule)

## Attach and detach persistent volumes

Run `kibo ws volume attach` to choose a running or stopped workspace and an available, unbound volume in its zone. The legacy attach form can use the default mount for the first volume. The positional form asks for a mount path when `--mount` is omitted in a terminal. Provide a mount path when adding another binding.

Run `kibo ws volume detach` to choose a workspace with attached volumes. With multiple bindings, choose one volume by its mount path or choose **All volumes**. Detaching the sole binding or all bindings asks for confirmation.

```bash
kibo ws volume attach wks_123 vol_123 --mount /data --restart --no-input --json
kibo ws volume detach wks_123 vol_123 --no-input --json
kibo ws volumes set wks_123 vol_123:/data vol_456:/cache --no-input --json
```

`attach` flags: `--mount` (absolute path, used with the positional volume), `--delete-with-workspace` to delete the volume along with the workspace, `--restart` to authorize the stop-and-start on a running workspace, and `--wait-timeout` for each transition (default `5m`). The legacy flag form `--volume` plus `--mount-path` still works. `detach` and `volumes set` accept `--restart` and `--wait-timeout` too.

The script form `kibo ws volume detach wks_123 --no-input --json` detaches all volumes. `ws volumes set` replaces the full list. With no arguments in a terminal, it picks a running or stopped workspace and confirms detaching all volumes. In automation, a workspace with zero bindings in the command sends an empty list immediately.

## Resize and read metrics

Run `kibo ws resize` to select a running, stopped, or failed workspace and change its vCPUs, memory, or root disk. Enter keeps the current value and only changed values are sent. The root disk can only grow. Supplying any resource flag skips the resource questions.

Run `kibo ws metrics` to pick a workspace and inspect the default metrics interval. Pass the optional interval bounds as RFC3339 timestamps.

```bash
kibo ws resize wks_123 --vcpus 4 --memory-mib 8192 --disk-mib 40960 --no-input --json
kibo ws metrics wks_123 --start 2026-11-16T10:00:00Z --end 2026-11-16T11:00:00Z --no-input --json
```

## Manage Pack bindings

Run `kibo ws packs set` without arguments to choose a workspace, see the available Pack IDs, and enter up to four unique IDs separated by commas or spaces. Leave the field blank or pass only a workspace to clear the list. Add or remove one binding with `kibo ws pack add` and `kibo ws pack remove`. A terminal can pick a Pack available in the workspace zone for add or choose among bound Packs for remove. Adding an existing binding or removing an absent one does nothing.

```bash
kibo ws packs set wks_123 node-22 kibotos-desktop-env --no-input --json
kibo ws packs set wks_123 --no-input --json # Clear the list
kibo ws pack add wks_123 node-22 --restart --no-input --json
kibo ws pack remove wks_123 node-22 --no-input --json
```

## Explicit Wait (`kibo workspace wait`)

Block until a workspace reaches any of the given statuses (`--status` accepts comma-separated values or repeated flags; `--timeout` defaults to `30` seconds and auto-chunks waits longer than `60` seconds):

```bash
kibo ws wait wks_01j9... --status available,failed --timeout 180 --json
```
