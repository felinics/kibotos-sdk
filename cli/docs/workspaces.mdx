Manage microVM workspaces using `kibo workspace` (aliases: `ws`, `workspaces`).

## Create a Workspace

Run `kibo ws create` with no flags in an interactive terminal for a guided prompt, or pass flags directly. Async lifecycle commands (`create`, `start`, `stop`, `delete`, `network`) **wait until completion by default** (pass `--no-wait` to return immediately):

```bash
kibo workspace create \
  -t python-3.12 \
  -n agent-sandbox \
  -z global-1 \
  --vcpus 2 --memory 4Gi --disk 20Gi \
  --network public_internet \
  --timeout 1h --timeout-action stop \
  -l team=ml -l env=dev \
  --json
```

### `kibo workspace create` Flags

| Flag | Required | Default | Description |
| --- | --- | --- | --- |
| `-t`, `--template <id>` | Yes (prompted in TTY) | — | Template ID (also accepts `template@revision`). |
| `--revision <rev>` | No | template default | Specific template revision ID. |
| `-n`, `--name <name>` | No | — | Human-readable workspace name. |
| `-z`, `--zone <zone>` | No | org default zone | Target zone ID. |
| `--vcpus <n>` | No | template default | vCPU count override. |
| `--memory <size>` | No | template default | Memory allocation (`4Gi`, `4096`; bare integer is MiB). |
| `--disk <size>` | No | template default | Root disk size (`20Gi`, `20480`; bare integer is MiB). |
| `--network <mode>` | No | `public_internet` | Outbound network mode: `public_internet` or `deny_all`. |
| `--volume <vol>` | No | — | Existing persistent volume ID or name to attach at creation. |
| `--mount-path <path>` | No | — | Mount path inside the workspace (e.g. `/data`; requires `--volume`). |
| `--delete-volume` | No | `false` | Delete the attached volume when this workspace is deleted (requires `--volume`). |
| `--timeout <dur>` | No | — | Auto-timeout duration (`1h`, `30m`, `3600`; bare integer is seconds). |
| `--timeout-action <action>` | No | — | Action on timeout expiration: `stop` or `delete` (requires `--timeout`). |
| `-l`, `--label <key=value>` | No | — | Workspace label (repeatable). |
| `--wait` | No | `true` | Block until workspace status reaches `available` (default `true`). |
| `--no-wait` | No | `false` | Return immediately without waiting for completion. |
| `--wait-timeout <dur>` | No | `5m` (`300s`) | Maximum duration to wait. |

## List and Inspect Workspaces

When neither `--limit` nor `--page-token` is provided, `kibo workspace list` automatically collects all pages across zones:

```bash
# List all available workspaces matching labels
kibo ws list --status available --zone global-1 --label team=ml

# Fetch a single page in JSON
kibo ws list --limit 20 --page-token <token> --json

# Inspect a specific workspace
kibo ws get wks_01j9...
```

Valid `--status` values: `creating`, `available`, `stopping`, `stopped`, `starting`, `deleting`, `failed`, `unknown`.

## Update Name and Labels

Specify at least one of `--name`, `--clear-name`, `--label`, or `--unset-label`. `--name` and `--clear-name` are mutually exclusive; `--label` and `--unset-label` are repeatable:

```bash
# Rename and update/remove labels
kibo ws update wks_01j9... \
  --name production-worker \
  --label env=prod \
  --unset-label temp

# Clear the workspace name (sets name to null)
kibo ws update wks_01j9... --clear-name
```

## Start, Stop, and Delete

All lifecycle commands accept a workspace ID or unique name (or prompt interactively in a TTY if omitted) and **wait by default** (pass `--no-wait` to return immediately, or `--wait-timeout <dur>` to override the `5m` wait window):

```bash
# Gracefully stop (waits until stopped by default)
kibo ws stop agent-sandbox

# Force immediate power-off (asks confirmation in TTY unless -y is passed)
kibo ws stop agent-sandbox --force -y

# Start a stopped workspace with a fresh 2-hour auto-stop timeout
kibo ws start agent-sandbox --timeout 2h --timeout-action stop

# Delete and wait until removed (returns status "deleted" when complete)
kibo ws delete agent-sandbox -y
```

## Update Timeout Policy

Extend or change the auto-timeout on a workspace (`--seconds` accepts durations like `2h` or bare seconds like `7200`; prompted in TTY if omitted):

```bash
kibo ws timeout agent-sandbox --seconds 2h --action stop
```

## Configure Outbound Network

Switch between `public_internet` and `deny_all` (waits until `network.applied` becomes `true` by default; pass `--no-wait` for immediate return):

```bash
kibo ws network agent-sandbox --mode deny_all
kibo ws network agent-sandbox --mode public_internet
```

## Attach and Detach Persistent Volumes

Volumes must be in the same zone as the workspace and attached or detached while the workspace is stopped:

```bash
# Stop the workspace, attach a volume, and start it again
kibo ws stop wks_01j9... --wait
kibo ws volume attach wks_01j9... \
  --volume vol_01j9... \
  --mount-path /data \
  --delete-with-workspace=false
kibo ws start wks_01j9... --wait

# Detach a volume (while workspace is stopped)
kibo ws volume detach wks_01j9...
```

## Explicit Wait (`kibo workspace wait`)

Block until a workspace reaches any of the given statuses (`--status` accepts comma-separated values or repeated flags; `--timeout` defaults to `30` seconds and auto-chunks waits longer than `60` seconds):

```bash
kibo ws wait wks_01j9... --status available,failed --timeout 180 --json
```
