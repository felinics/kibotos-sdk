Reference for `kibo volume`, `kibo exposure`, `kibo zone`, and `kibo template`.

## Persistent Volumes (`kibo volume`)

Aliases: `vol`, `volumes`.

### Create a Volume

`-s`/`--size` accepts GiB integers (`50`) or units (`50Gi`, `1Ti`), and is prompted interactively in a TTY if omitted. Waits until status reaches `available` by default (`--no-wait` returns immediately; `--wait-timeout` defaults to `5m`):

```bash
kibo vol create \
  -s 50Gi \
  -n datasets-cache \
  -z global-1 \
  -l team=ml \
  --json
```

### List and Inspect Volumes

```bash
# List unattached volumes in a zone
kibo vol list --zone global-1 --attached false --label team=ml

# Single page with explicit pagination
kibo vol list --limit 25 --page-token <token> --json

# Get full volume details
kibo vol get vol_01j9...
```

### Update a Volume

```bash
kibo vol update vol_01j9... \
  --name datasets-v2 \
  --label tier=hot \
  --unset-label legacy

# Clear the volume name
kibo vol update vol_01j9... --clear-name
```

### Resize a Volume

Grows an `available` volume to a larger size (accepts bare GiB or `100Gi`/`1Ti`). Waits until status returns to `available` by default (`--no-wait` to skip):

```bash
kibo vol resize datasets-cache -s 100Gi
```

### Delete and Wait on a Volume

Valid volume statuses follow native Kibotos 1:1 semantics: `creating`, `available`, `attached`, `resizing`, `deleting`, `failed`, `lost`, `unknown`. `workspace_id` expresses workspace binding; `available` means ready and not mounted to a running workspace; `attached` means mounted to a running workspace; `lost` means the underlying storage pool was lost (read/delete only).

```bash
# Wait explicitly for target status(es) (default --timeout: 30s)
kibo vol wait vol_01j9... --status available,failed --timeout 2m

# Delete an unbound volume (waits until removed by default; prompts confirmation in TTY unless -y)
kibo vol delete vol_01j9...
```

## HTTPS Port Exposures (`kibo exposure`)

Aliases: `exp`, `exposures`.

Expose any TCP port (`1`–`65535`) inside an `available` workspace on a temporary public HTTPS URL (`*.kibo.run`).

### Create an Exposure

Pass workspace (ID or name) and port via `-p`/`--port` or as the second positional argument (both prompted interactively in a TTY if omitted). `--ttl` accepts durations (`1h`, `30m`) or seconds (API default: `3600` seconds):

```bash
kibo exp create wks_01j9... 8080 --ttl 1h --json
# Equivalent:
kibo exp create wks_01j9... --port 8080 --ttl 3600 --json
```

### List, Get, and Revoke Exposures

```bash
# List active exposures for a workspace
kibo exp list wks_01j9...

# Include revoked exposures
kibo exp list wks_01j9... --include-revoked --limit 20

# Inspect a specific exposure
kibo exp get wks_01j9... exp_01j9...

# Revoke an active exposure immediately
kibo exp revoke wks_01j9... exp_01j9...
```

## Compute Zones (`kibo zone`)

Aliases: `zones`.

List compute zones accessible to your organization (`--limit` and `--page-token` optional; auto-paginates when omitted). Table output includes `ID`, `NAME`, `REGION`, `COUNTRY` (ISO 3166-1 alpha-2 code or `-` when unset), `STATUS`, and `DEFAULT`; JSON output includes the nullable `country` field:

```bash
kibo zone list
kibo zone list --json
```

## Workspace Templates (`kibo template`)

Aliases: `tpl`, `templates`.

### List and Inspect Templates

Filter by `--owner` (`platform` or `organization`) and/or `--zone`:

```bash
# List platform templates available in global-1
kibo tpl list --owner platform --zone global-1

# Inspect a template's default/latest revision and supported zones
kibo tpl get python-3.12 --json
```

### Inspect Template Revisions

```bash
# List revisions for a template
kibo tpl revisions python-3.12

# Inspect a specific revision (build status, size_mib, zones, ready_at)
kibo tpl revision python-3.12 rev_20260101 --json
```
