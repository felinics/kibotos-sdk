title: Exec, Files, and Tunnels
description: Run commands, move files, forward local connections, and open the browser desktop on Kibotos workspaces with kibo.

These commands work on available workspaces. If you omit the workspace in an interactive terminal, `kibo` opens a picker. Supply a workspace ID or unique name for automation.

## Open a login shell

```bash
kibo shell
kibo shell devbox --workdir /app --user app --env MODE=dev
kibo shell wks_123 --start --wait-timeout 2m --no-input
```

`kibo shell` picks a running or stopped workspace, showing running workspaces first. It opens a Bash login shell when Bash is installed and falls back to `sh`. On a stopped workspace, a terminal offers to start it and wait for availability. With `--no-input`, pass `--start` to allow that transition. Shell sessions require Unix terminal stdin and terminal output mode.

## Run a command

```bash
kibo exec                         # Pick a workspace and enter one shell command
kibo exec -- uname -a              # Pick a workspace and run this argv
kibo exec -it                      # Pick a workspace and open a login shell
kibo exec devbox -it -- /bin/sh     # Open a PTY for an explicit command
```

`kibo exec devbox` asks for a command and runs it with `/bin/sh -c`. Arguments after `--` are sent as argv. A bare `-it` starts Bash if installed and otherwise starts `sh`. The PTY requires a local Unix terminal and forwards size changes. Use `--workdir`, repeatable `--env`, `--timeout` in seconds, or `--user` to tune execution.

```bash
kibo exec wks_123 --no-input --json --workdir /app --env MODE=test --timeout 60 -- python3 main.py
printf 'hello' | kibo exec wks_123 --no-input --json --stdin - -- cat
kibo exec wks_123 --no-input --json --stream --timeout 900 -- python3 -u main.py
```

The default synchronous timeout is 30 seconds. Timeouts over 600 seconds require `--stream` or `-it`. `--stdin` takes literal text, or `-` to read up to 3 MiB from local stdin. `--stream --json` emits one event per line as an object with `type` and `data`. `-it` cannot be combined with `--stream`, `--stdin`, or `--json`. `exec` forwards the remote exit status, reports timeouts as `124`, and reports signals as `128 + signal`.

## Browse and transfer files

| Interactive command | After choosing a workspace |
| --- | --- |
| `kibo files ls` | Lists `.` in the selected user's home directory |
| `kibo files stat` or `kibo files get` | Asks for the remote path. Downloads default to stdout |
| `kibo files put` | Asks for the local path and remote destination. The default destination uses the local filename |
| `kibo files mkdir` | Asks for the directory path |
| `kibo files mv` | Asks for the source and destination paths |
| `kibo files rm` | Asks for the remote path and confirms deletion |

Use `--user` to select a guest user. Optional `--depth`, `--range`, `--mode`, and `--create-only` stay on flags. With `--json`, downloads require a local destination and return metadata. To write raw bytes to stdout, use `--no-input` with a workspace and path and omit `--json`. Use `-` as the upload source to read from stdin.

```bash
kibo files ls wks_123 /app --depth 2 --no-input --json
kibo files stat wks_123 /app/main.py --no-input --json
kibo files get wks_123 /app/output.log ./output.log --range bytes=0-1023 --no-input --json
kibo files put wks_123 ./main.py /app/main.py --mode 0644 --create-only --no-input --json
kibo files mkdir wks_123 /app/archive --mode 0755 --no-input --json
kibo files mv wks_123 /app/output.log /app/archive/output.log --no-input --json
kibo files rm wks_123 /app/archive/output.log --no-input --json
```

## Copy a file with `kibo cp`

```bash
kibo cp ./report.txt devbox:/data/
kibo cp wks_123:/data/report.txt ./reports/ --no-input --json
kibo cp wks_123:/data/report.txt - --no-input
```

Specify one local path and one `workspace:path` operand. Uploads to `.` or a path ending in `/` keep the local filename and have a 1 GiB limit. Downloads into an existing directory or a path ending in `/` keep the remote filename. A destination of `-` streams raw bytes to stdout. Use a local destination with `--json` for download metadata. Both directions accept `--user`. Uploads also accept `--mode` and `--create-only`.

## Forward a local port

Run `kibo tunnel` to choose an available workspace and enter a guest TCP port. Enter accepts `8080`. The default local listener is `127.0.0.1:18080`.

```bash
kibo tunnel devbox 8080
kibo tunnel wks_123 --remote 8080 --family ipv4 --listen 127.0.0.1:18080 --no-input --json
kibo tunnel wks_123 --unix-path /run/app.sock --listen 127.0.0.1:18081 --no-input --json
```

Use a positional port or `--remote` for guest loopback TCP. Use `--unix-path` for a guest Unix socket. Each local connection opens an authenticated WebSocket. The tunnel stays open until cancelled. Startup prints `Listening on <addr>`, writes the address alone with `-q`, or emits `{"workspace_id":"...","listen":"..."}` with `--json`.

## Open a temporary HTTPS URL

```bash
kibo open
kibo open devbox 8080 --ttl 30m
kibo open wks_123 8080 --no-input --no-open
kibo open wks_123 8080 --no-input -q
```

`kibo open` picks an available workspace and defaults the prompted port to `8080`. It reuses an active exposure for that port or creates one if needed. `--ttl` sets the lifetime of a new exposure. Human output prints the URL and opens the browser unless you pass `--no-open`. `-q` prints the bare URL and `--json` returns the exposure object. Both skip browser launch.

## Open the browser desktop

```bash
kibo desktop devbox --open
kibo desktop wks_123 --no-input -q
```

`kibo desktop` returns a direct, full-window Dashboard URL. It attaches the Desktop Pack when needed. See the workspace guide for enabling Desktop at creation and activating the Pack on an existing workspace. [Remote desktop](workspaces#remote-desktop)
