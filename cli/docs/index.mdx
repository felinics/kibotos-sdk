`kibo` is the official command-line interface for **Kibotos**. Manage workspaces, run commands, transfer files, open tunnels, and configure volumes, Packs, exposures, and networking from your terminal, CI pipeline, or AI agent.

## Installation

### Download a Pre-Built Binary

Pre-built archives (`linux`, `darwin`, `windows` for `amd64` and `arm64`) with `SHA256SUMS` are published on [GitHub Releases](https://github.com/felinics/kibotos-sdk/releases) under tags `cli/v*`.

Download and unpack the archive for your platform, then place `kibo` on your `PATH`:

```bash
tar -xzf kibo_<version>_<os>_<arch>.tar.gz
sudo mv kibo /usr/local/bin/kibo
kibo --version
```

### Build from Source

Requires Go 1.24 or later:

```bash
git clone https://github.com/felinics/kibotos-sdk.git
cd kibotos-sdk/cli
go build -o /usr/local/bin/kibo ./cmd/kibo
```

## Quickstart

```bash
# 1. Sign in via your browser (Device Authorization Flow)
kibo login

# 2. Verify your active identity and accessible zones
kibo whoami

# 3. Discover available zones and templates
kibo zone list
kibo template list

# 4. Create a workspace: pick a template and enter devbox as its name
kibo ws create

# 5. Run a command and open a login shell
kibo exec devbox -- uname -a
kibo shell devbox

# 6. Copy a file into the home directory, then expose port 8080 over a temporary HTTPS URL
kibo cp ./app.py devbox:.
kibo open devbox 8080 --ttl 1h

# 7. Clean up (waits until deleted by default; pass --no-wait to return immediately)
kibo ws delete devbox
```

## Global Flags

Available on every `kibo` command:

| Flag | Default | Description |
| --- | --- | --- |
| `--json` | `false` | Output strictly valid JSON to `stdout` (shorthand for `-o json`). |
| `-o`, `--output <format>` | `table` | Output format: `table` or `json` (env: `KIBO_OUTPUT` / `KIBOTOS_OUTPUT`). |
| `-q`, `--quiet` | `false` | Output only the primary value, such as a resource ID or Desktop URL, and suppress progress messages. |
| `--no-input` | `false` | Disable interactive prompts and fail fast on missing inputs (env: `KIBO_NO_INPUT` / `KIBOTOS_NO_INPUT`). |
| `-y`, `--yes` | `false` | Skip interactive confirmation prompts on destructive actions. |
| `--no-color` | `false` | Disable colored output (also respects `NO_COLOR`). |
| `--profile <name>` | active profile | Named profile from `config.json` to use for this command. |
| `--org <id>` | active profile org | Override the target organization ID (`X-Kibotos-Organization`, env: `KIBO_ORG` / `KIBOTOS_ORG`). |
| `--api-key <key>` | — | Override the Kibotos API key (`kb_...`) for this invocation. |
| `--api-url <url>` | `https://api.kibo.to/v1` | Override the Kibotos v1 API base URL. |

`kibo --version` and `kibo -v` print the same details as `kibo version`: CLI version, Go SDK version, Go runtime, platform, and the build commit and date when available. `kibo version --json` returns them as an object, and `kibo version -q` prints only the CLI version.

## Interactive vs. Non-Interactive Mode

In a terminal, `kibo` asks for essential missing inputs on stderr. Pick resources with the arrow keys and Enter. Use `--yes` to skip destructive confirmations and supply any known inputs to skip their questions.

For scripts and AI agents, supply required arguments and flags with `--no-input --json` or use `-q` to capture IDs. Prompts are disabled when stdin or stderr is a non-TTY, the output format is JSON, or `--no-input`, `-q`, `TERM=dumb`, `CI`, `KIBO_NO_INPUT`, or `KIBOTOS_NO_INPUT` disables them. Missing required inputs fail with exit 2 and a hint before authentication.

A running workspace can be stopped and restarted for a resize, volume update, or Pack change after one `[Y/n]` confirmation (yes by default). A shell or desktop on a stopped workspace offers to start it. Declining cancels before applying changes. Automation must pass `--restart` or `--start` to authorize these transitions. See [Apply configuration changes on a running workspace](workspaces#apply-configuration-changes-on-a-running-workspace).

## Scripting & JSON Mode

Pass `--json` (or `-o json`, or set `KIBO_OUTPUT=json`) whenever piping output to `jq`, scripts, or AI agents:

- `stdout` contains JSON on success. `exec --stream --json` emits one JSON event per line. `files get --json` requires a local destination and emits download metadata.
- `desktop --json` and `open --json` include the URL in `url`. Both commands print a bare URL with `-q`. `open` launches a browser only in human output mode unless you pass `--no-open`.
- Progress updates, interactive login URLs/codes, multi-zone warnings, and structured error envelopes are always written to `stderr`.
- All async lifecycle commands wait for completion by default; pass `--no-wait` (or `--wait=false`) to skip the final wait. A restart still waits for the workspace to stop before sending the start request.

In `--json` mode, errors are written to `stderr` using a consistent JSON envelope:

```json
{
  "error": {
    "code": "invalid_state",
    "message": "Workspace must be stopped before attaching a volume",
    "exit_code": 1,
    "status": 409,
    "request_id": "req_01j9...",
    "retryable": false,
    "hint": "Stop the workspace first with `kibo workspace stop <id> --wait`."
  }
}
```

## Exit Codes

| Exit Code | Meaning | Recommended Handling |
| --- | --- | --- |
| `0` | Success | Parse `stdout` output. |
| `1` | API or runtime error | Inspect `stderr` (`error.code`, `error.retryable`, `error.request_id`). Retry briefly if `retryable` is `true`. |
| `2` | Usage, argument, or flag validation error | Fix command flags or arguments before retrying. |
| `3` | Unauthenticated (no credentials or HTTP `401`) | Run `kibo login` or configure `KIBOTOS_API_KEY`. |

`exec` also forwards the remote process status, including `124` for a timeout and `128 + signal` for signal termination.
