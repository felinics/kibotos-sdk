## Packs

Run `kibo pack list` to browse Packs. Run `kibo pack get` to pick a Pack by ID, with its version and available zones shown. Pass `--revision` to inspect a specific revision.

```bash
kibo pack list --zone global-1 --no-input --json
kibo pack get node-22 --no-input --json
kibo pack get node-22 --revision r42 --no-input --json
kibo ws packs set wks_123 node-22 kibotos-desktop-env --no-input --json
kibo ws pack add wks_123 python-3.12 --restart --no-input --json
kibo ws pack remove wks_123 node-22 --no-input --json
```

A workspace can bind up to four unique Pack IDs. Use `ws pack add` and `ws pack remove` to change one binding or `ws packs set` to replace the ordered list. Both `pack` and `packs` work under `ws`. Use `--restart` in automation when the new list should take effect immediately on a running workspace. [Workspace configuration](workspaces#apply-configuration-changes-on-a-running-workspace)

## SOCKS5 egresses

Run `kibo egress create` to enter a SOCKS5 address and optionally name it. Use `egress get`, `egress update`, or `egress delete` without a reference to choose an egress. An update without flags prompts for a new name. Deletion asks for confirmation in a terminal.

```bash
kibo egress create --address proxy.example.com:1080 --name proxy --username app \
  --password-env PROXY_PASSWORD --tls --udp-enabled --no-input --json
kibo egress list --zone global-1 --no-input --json
kibo egress get egr_123 --no-input --json
kibo egress update egr_123 --name proxy-east --no-input --json
kibo egress update egr_123 --address proxy-east.example.com:1080 --username app \
  --password-env PROXY_PASSWORD --tls --udp-enabled --drain-seconds 60 --no-input --json
kibo egress delete egr_123 --no-input --json
```

Endpoint flags replace the complete SOCKS5 configuration. Supply credentials and TLS settings again when applicable. Use `--address` for the host and port, `--password-env` to read the password from an environment variable (preferred over `--password`), `--tls` to connect over TLS, `--server-name` for a TLS server-name override, and `--ca-cert` for a PEM trust file of at most 64 KiB. `--udp-enabled` lets a UDP resolver send DNS through the egress. `--drain-seconds` (`0`–`3600`) applies to updates only. `--zone` and repeatable `--label` are optional creation flags. Update metadata (`--name`, `--clear-name`, `--label`, `--unset-label`) and the endpoint in separate invocations.

## DNS resolvers

Run `kibo resolver create` to choose a DNS protocol, enter its upstream, and optionally name the resolver. Use `resolver get`, `resolver update`, or `resolver delete` without a reference to choose a resolver. A flagless update prompts for the new name. Deletion asks for confirmation in a terminal.

```bash
kibo resolver create --protocol udp --address 10.0.0.53:53 --name internal --no-input --json
kibo resolver create --protocol https --url https://dns.example/dns-query --name doh --no-input --json
kibo resolver list --no-input --json
kibo resolver get rsv_123 --no-input --json
kibo resolver update rsv_123 --name internal-east --no-input --json
kibo resolver update rsv_123 --protocol tls --address dns.example:853 --no-input --json
kibo resolver delete rsv_123 --no-input --json
```

For UDP, TCP, or TLS, provide a host or `host:port` via `--address`. HTTPS takes an endpoint via `--url`. Use separate update invocations for metadata (`--name`, `--clear-name`, `--label`, `--unset-label`) and full endpoint replacement.

## Referencing networking resources

Egress and resolver commands accept a unique name or canonical ID. Names match exact case first, then case-insensitively. If a name is ambiguous, use a picker in a terminal or supply an ID in automation. List commands collect all pages by default. Use `--limit` or `--page-token` to fetch one page.

Bind resources by ID when updating the outbound policy. A resolver ID alone uses a direct path. Append `=egress_id` to route its DNS traffic through that egress. Delete resources after removing their references from workspace policies.

```bash
kibo ws network wks_123 --mode public_internet \
  --egress egr_123=10.0.0.0/8 --resolver rsv_123=egr_123 --no-input --json
```

A policy takes at most one `--egress` and one `--resolver`, and a resolver routed with `=egress_id` must name the egress from the same command.

## Edit one workspace network rule

```bash
kibo ws network allow wks_123 203.0.113.0/24 --no-input --json
kibo ws network deny wks_123 198.51.100.2 --remove --no-input --json
kibo ws network use-egress wks_123 egr_123 10.0.0.0/8 --no-input --json
kibo ws network use-resolver wks_123 rsv_123 --via-egress --no-input --json
kibo ws network use-resolver wks_123 --clear --no-input --json
kibo ws network use-egress wks_123 --clear --no-input --json
```

Incremental edits preserve the network mode and the other rule lists. Switch to `public_internet` before adding rules to a workspace in `deny_all` mode. `allow` and `deny` deduplicate addresses and accept `--remove`. `use-egress` and `use-resolver` accept IDs or unique names and replace or clear the selected rule. Provide destination CIDRs explicitly in automation. In a terminal, omitting them opens a prompt with `0.0.0.0/0` as the default. `--via-egress` uses the configured egress for DNS. Clear or reroute a resolver that depends on an egress before removing that egress.

Running workspaces wait for `network.applied` by default. Pass `--no-wait` to return after sending the change. A stopped workspace applies its policy on the next start.
